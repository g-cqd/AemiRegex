| The DFA agrees with the Pike VM on every pattern | the new generated corpus against Go | **REFUTED**: `(?i:\B*?\B|a)*` on `BaBA`: Go (and the Pike VM) `[0,0] [1,1] [2,2] [3,3] [4,4]`, the DFA `[0,0] [1,2] [3,4]` |

### The bug

The DFA resolves an assertion one byte late. Its state lists the assertion as pending, and the next transition expands what lies behind it
with a fresh visited set. When an empty-width loop passes through an assertion, that expansion goes round the loop once more than the Pike VM
would (the Pike VM builds the whole closure with one visited set), and the extra pass puts the second alternative ahead of the empty match.
Without an assertion in the loop the two builds are identical. Fix: `DFAPlan.isEligible` refuses a program with an empty-width cycle that
contains an assertion (an iterative search over jump, split, save and assertion edges); those patterns take the Pike VM, which is correct.
Regression test first (red: the DFA answer, plus three eligibility rows), then the fix.

rule removed: each turned the suite red (1, 1 and 5 issues).

None new in the process; the gate caught one of mine at once (the overload rename above).

## The Rust gap, first item: end-anchored patterns (roadmap 0006)

| Claim | Probe | Verdict |
|---|---|---|
| A pattern whose matches all end at `\z` can skip the forward scan | tests first (eligibility table, agreement with the Pike VM from every start offset, a 2 MB haystack), then the implementation | Holds. `[ \t]*$` 1.77 ms to 0.06 ms; the other rows did not move |
| Rust does the same | not read, not probed | **Open**: only the measured row is claimed |

Detection is a backward walk from `match` over empty-width edges that stops at an end-of-text assertion and answers "not anchored" on reaching
a byte-consuming instruction or the first instruction. Conservative: `a$b?` is not recognised although all its matches do end at the end.
Mutations (baseline green first, 117 tests): every pattern called anchored (8,369 issues); a byte-consuming path ignored (4); the match start
taken as the search offset (49). **Two of my first three mutation scripts did not apply** (the formatter had re-indented the code I anchored
on) and printed "NOT CAUGHT" for mutations that were never made; the script now prints "mutation applied" and an unapplied one stops.
