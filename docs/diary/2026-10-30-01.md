# Diary — 2026-10-30 (01)

## Whole matches are whole-string matches (roadmap 0015)

swift-search matches user patterns against declaration names, and checking the method it would call found that
`wholeMatch` was leftmost-first and then a range check: `a|ab` on `ab` gave nil, where Swift `Regex` and RE2's
`FullMatch` give the whole string. `Pattern` now runs a whole-string twin, compiled on first use. The backtracker starts
only at 0, and a `match` away from the end backtracks. `AtomicLazyReference` was tried first and lost: its `load()` was not
specialized and looked up generic metadata on every call, about 450 ns. A plain atomic state with acquire and release
replaced it. The probe went from 221–240 ns a name to 185–194. A failing whole match on the backtracker no longer
scans every start. swift-search's `NameExpression` still wraps the expression in `^(?:…)$` by hand; it can call
`wholeMatch` when it takes this revision.

## Upstream moved under us

While this work was local, four commits landed upstream, each moving the aemi pin so MacFS can share one aemi revision,
up to `2fbe4e4`. They touch only `Package.swift`, so the fast-forward was clean. AemiJSON still pins this package at
`923d23f` with aemi `04e49d1`; it has to move both in one commit (AemiJSON roadmap 0010), because SwiftPM takes one
revision per package.

## What the family decided about patterns

analyzerkit ADR-0027 settles P9 (linear-time patterns) as a deletion, not a promotion. deadwood's `SafeRegex` (a length
cap and an antipattern filter) and `RegexCache` guard Swift `Regex` against backtracking, and this engine has none to
guard against. They go in deadwood's migration. The first consumers of 0016 (`requiredLiterals`) are swift-search's
index query (its H4, swift-search roadmap 0009) and, later, deadwood's filters; 0017 (the constant cost on short
inputs) matters to the same name-matching loop.
