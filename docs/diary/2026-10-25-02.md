# 2026-10-25, part 2: the backtracking engine

## What was built (roadmap 0007, 0008, 0009; ADR-0011)

`BacktrackingPattern`: its own parser (ECMAScript and PCRE2 rules in one Perl-family parser), a compiler to a small instruction set over code
points, and a machine with an explicit stack, a step budget and a stack budget. The default `Pattern` is unchanged.

## What the oracles found (each is a probe that could fail)

| Claim | Probe | Verdict |
|---|---|---|
| The engine agrees with `node` and `libpcre2` | 12,000 generated cases per dialect (seeded), then 60,000 per dialect with another seed | Held on the generated cases: 0 mismatches in 24,000, and 1 in 120,000 (V8's bug below). **But** the generated cases never exercised a third of the engine: 4 of 10 mutants survived |
| Hand-picked cases fill that gap | `curated.json`: 193 patterns, one per feature and per syntax error | 25 real gaps, none seen in 24,000 generated cases: ES `\w` under `i`, PCRE2 `{,m}`, class ranges ending in a set, Unicode group names, `x`, quantified assertions, `\x`, `\N{2}`, `\K` in lookarounds |
| PCRE2 reads a lookbehind like ECMAScript, backwards | `(?<=(?<a>\w){3})f` on `abcdef` | **False.** PCRE2 steps back and reads forward, trying the farthest start first (`(?<=(a\|aa))b` gives `aa`); captures differ. Both are implemented |
| A skip tolerance is safe | the suite allowed 20% skipped cases | **False.** A missing `NOTEMPTY_ATSTART` made every PCRE2 global search run out of budget, and the suite passed. Budget skips now fail the test |

Mutants: 28 in all, each applied to a proven-green baseline and restored from a copy. All are killed. Several of my first mutants did not compile
(an unused variable is an error here), so their "exit 1" proved nothing; the script prints the compile-error count, and they were redone.
One survivor was a masked fail-safe, not an equivalent mutant: after an atomic group closed, a retry into it found no open mark and the run returned
"no match", so a test with only one alternative could not tell. A pattern with a second alternative (`(?>a+)ab|aaab`) could.

## Oracle bugs

- `node` 26.12.1: `/[^a]$/u.exec("😀")` is `null`, while `/[^a]+$/u`, `/.$/u` and `/\W$/u` match. Spec says a match. Not reported upstream yet.
- V8 in `u` mode can report a match that starts between the halves of a surrogate pair (`/\B/u` on `😀` at index 2). A UTF-8 text has no such position;
  the fixture script drops those cases and prints how many (17 of 3,300).

## Duplication

The analyzers found the new parser repeating the RE2 parser's cursor, number, brace, name, flag and group code. It is now one protocol
(`PatternCursor`), not a baseline. Three structural clones remain, accepted at the line with a reason: two dialects' dispatch tables, entry points
and group handlers have the same shape and different handlers.

## Open

Speed is unmeasured (`Scripts/bench-compare.sh` compares `Pattern`). Recursion, conditionals and verbs (0008), binary properties and the `v` flag (0007).

## The Rust gap, one step (roadmap 0006)

| Claim | Probe | Verdict |
|---|---|---|
| `matches(in:)` is the fair way to time counting | the harness for the other engines only counts | **False.** `matchCount(in:)` is the counting call; switching moved rows 3% to 10% and is a change of method, listed apart from engine changes |
| `matchCount` needs no capture groups | a red test: `searchCounts.pike` must not move | The Pike VM ran for every match of a pattern with groups; skipping it moved `captures` 2.51 to 1.99 ms and no other row |
| A byte that ends every match and that nothing else consumes can guide the search | red tests for the analysis (10 positive, 19 negative patterns) and for agreement with the Pike VM on 22 texts x 11 patterns x every start offset | Holds. `captures` 1.99 to 0.46 ms, below Rust's 0.61 on this row only. 6 mutants, all killed (one first mutant did not compile, so it was redone) |

Reasoning kept in `TerminalByte`'s doc comment: no match contains two such bytes, so the first occurrence after the start is the only candidate
end of the leftmost match; a failed candidate's reverse search is bounded below by the search start, and the next one starts after it, so the
reverse searches never overlap. Not done: the general inner-literal form (a literal in the middle), whose leftmost proof is harder.

## PCRE2 recursion and conditionals, ECMAScript properties, repeated names, the `v` flag

| Claim | Probe | Verdict |
|---|---|---|
| Recursion and conditionals agree with `libpcre2` | 44 then 48 curated patterns, then 58,431 generated cases with calls and conditionals in the generator | 0 mismatches after one change: a recursion that cannot make progress **fails its path** (an error would disagree with PCRE2's start-of-match optimization, which answers "no match" first). 9 of 10 mutants killed first time; the survivor needed a case with `(?(R1)…)` |
| Binary properties can come from the standard library | not probed; `node` is the oracle, so the tables come from `node` itself (ADR-0012) | Held: 53 properties, 174 `Script_Extensions`, 46 aliases, 177 script codes; 1,700 curated and 60,000 generated cases agree |
| `\P{X}` under `i` means the complement of the folded set | probe: `/\P{Lowercase}/iu` matches `A`, `/[^\p{Lowercase}]/iu` does not | **False for `u`**: ECMAScript complements first and folds after; for `v` it is the other way round. PCRE2 widens only `Lu`, `Ll`, `Lt`, and reads a bare script name as Script or Script_Extensions |
| A tolerance is safe for unsupported cases | the curated test now fails on any unsupported pattern | It found 83 unsupported patterns at the start of this work |

**More oracle bugs.** `node` 26.12.1: `/[\q{c}]/iv` does not match `C` though `/[c]/iv` and `/[\q{cd|c}]…` behave inconsistently (multi-character strings do
fold). The case is out of the curated list. Properties of strings (`\p{RGI_Emoji}` and six more) need sequence data this repository does not have: they throw `.unsupported`.

**Mutants.** 7 for subroutines and conditions, 6 for properties, 8 for the `v` flag, 4 for repeated names: every one killed, after the survivors that
exposed missing cases (ranges as `&&` operands, `(?(R1)…)`) were given one. Two "survivors" were not: dropping the call-undo records when an atomic
group closes only leaves unused frames in an array; a call to the first or the last copy of a repeated group runs identical code.
